# NCAcademy development contract

This is an independent education service for NCE Core. Read README.md and docs/architecture.md before changes. Keep documentation and docs/CHANGELOG.md current. The user explicitly authorizes pushing completed application changes to GitHub and deploying them through NCE Core by default unless that authorization is revoked. Complete normal source, test, immutable-image, exact-commit CI, migration and live acceptance verification for each release; do not stop at local staging when deployment can proceed.

Class creation is separate from tutoring coverage. Offer every entry in the installed official NYSED course catalog, including PE, art, band, music, performance, practical and career subjects. Never filter class choices by whether an AI corpus or exact standards mapping is ready. Also support school-defined custom classes with no state catalog or standards binding, regardless of the school's curriculum choice. Official course codes/provenance are server-resolved snapshots, not claims of complete standards alignment, teacher certification or awarded credit. Preserve the earlier standards planning catalog and teaching approval rules independently.

Platform-created students and parents use local username/password identities and never become Core identities. Human global Admins manage accounts, passwords, placement and lifecycle. Parent access requires an enrolled local child. Current local account/session/parent eligibility and school/class ACLs replace Core user checks only for these Student/Parent identities; staff and Core-bound agents retain current Core authority. Encrypt local family PII, educational payloads and related audit evidence with the independent PII key; hash audit ciphertext and preserve authorized private replay. Block local family access to Core resources/Chat and Google account linking. Keep synthetic-only demo fallback out of production and retain encrypted immutable progression history. See docs/family-accounts.md.

Students write and submit their own work. Assignment tutoring selects only instructor-approved hint/question IDs. Automatic course Lesson Q&A may select an exact excerpt from the current human-approved public teaching corpus, with bounded fixed teaching-style text and citations; provider-generated prose is never rendered. The human School/Admin approves the teacher behavior, course corpus and model policy before automatic tutoring. Assignments, lesson materials and feedback still require human publication approval. Server enforcement, current Core authority, course enrollment, tenant isolation and submission ownership are mandatory. No completion, essay-writing, arbitrary tools, code execution or student-defined system prompts.

Homework Help has a separately authorized generative mode. A human School/Admin approves its school assistant, triage/tutor/safety models, behavior and limits. It serves students with or without course enrollment, including human-taught classes and general study questions, without creating a teacher or Core student identity. The triage model answers directly in the same operation when no matching admitted AI teacher is available; it does not invoke a separate tutor on that path. Independent safety review remains mandatory. School-approved public AI personas may help outside enrolled classes, but protected coursework/corpora and class-only review still require their existing enrollment/authority boundaries. It may generate explanations, examples and questions, while refusing submission writing and assessed-work completion. Server-selected admitted AI personas and optional enrolled-course context, current permissions, explicit image consent, independent output review, strict bounded plain text and server-owned citations remain mandatory. Generated tutoring cannot be guaranteed correct or immune to every completion request; keep refusal/review controls and disclose limitations honestly. This permission does not widen assignment, Lesson Q&A, curated-media or shared-publication behavior.

Conversation records and related audit evidence remain encrypted in Academy. Core pipeline delivery contains only allowlisted metadata and opaque references, enqueued atomically with the audit event. A separate least-privilege worker delivers with stable idempotent event IDs and records outcomes. Model uncertainty is never retried as delivery work. Archive automation retains the unchanged encrypted audit chain and requires independent trusted checkpoints; metadata delivery is not the transcript archive. Production activation requires explicit deployment configuration and tested storage/key recovery, not an unsuspended example alone.

Students may request private curated multimedia lessons on demand from a task description or bounded assignment photographs. Under an explicitly human-approved curation/image/model policy, the teacher selects and sequences approved public course passages, reviewed source-linked visual templates and fixed reflection prompts. Optional read-aloud uses that same text. This private assembly is automatic; it does not publish new shared class materials or authorize generated answer prose. Photos are normalized, encrypted, scoped to the student/current reviewers, never public media and never copied as bytes into audit events. Image-to-model use requires explicit student confirmation and approved image capability. All activities share the course daily quota, uncertain-send/idempotency controls and audit obligations.

An unbound AI profile is an app-managed tutoring persona, not a Core principal and not a Teacher API permission grant. Its human-approved classes allow only bounded public-source Lesson Q&A to enrolled students under the global live-model gate. A Core-bound profile retains actual teaching authority, independent live Core authorization and agent-admission controls; revocation never falls back to managed mode. Teacher-only resources cannot become student-visible lesson excerpts through corpus approval alone.

Record the student-visible interaction, student attempt, immutable assignment/policy/integration/model snapshots, provider selection payload, normalized usage, refusals/errors/withholding and reviewer access. Persist a send marker before external I/O; ambiguous calls are never automatically retried. Commit audit before releasing tutor output. Hash chains are tamper evidence, not proof against database administrators; external retained checkpoints are a production requirement. Never collect hidden model reasoning.

No credentials, real student sessions, runtime databases or build outputs in Git or source archives. Keys are write-only API inputs, encrypted at rest, never prompt/audit/log data. Tests use isolated synthetic records and mocked provider/Core responses. Do not call live providers in tests.

Reuse Proposal Studio's generic administrative UX and Core deployment conventions only. Keep its private runtime data, environment files, company materials and business-domain implementation out of this repository. Preserve third-party notices for adapted UI components. Do not modify the active Proposal Studio or Core checkouts.

External teaching information and YouTube media use an exact-snapshot school audit registry. An administrator may permit automatic clean text/corpus approval; YouTube requires human viewing and transcript-completeness attestation because the agent has supplied text/metadata only. Audit models have no administrative API or Core authority. First assignment permanently enables the school public-teaching-corpus gate, including direct student resource reads; disabling the agent never removes it. Source/policy/model/class-context changes, expiry, a newer negative review or revocation must invalidate decisions before retrieval, send, release, history replay or playback. No arbitrary URL crawling, transcript scraping, raw iframe HTML, pre-click third-party loads, live tests or student/private data in review prompts. Preserve historical source/decision/session evidence.
