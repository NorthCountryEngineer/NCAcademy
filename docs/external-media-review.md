# YouTube lessons and the school audit agent

Teachers can submit YouTube lessons and supplied external teaching text from a class's **Reviewed resources** activity. Human School/Admin users assign a school audit agent from **School settings → External review**. The agent reviews public teaching evidence against a fixed rubric before publication. It is a separate application configuration and model purpose, not a teacher profile, Core identity, administrative API principal or credential issuer.

## Assigning the agent

Select a named school model connection and model, give the reviewer a name, and set bounded input, output, daily request/reservation and review-expiry limits. Optional policy notes describe local suitability requirements. Saving creates an immutable policy revision and makes external review mandatory for that school's public teaching corpus. Disabling the agent or editing ordinary school settings does not remove this requirement. Existing model and Core admission gates remain independent; assignment does not send a test request or enable live traffic.

Human final approval is the initial policy. An administrator may explicitly clear **Require human approval for text and corpus materials**. Under that policy, a valid clean agent approval automatically publishes the exact supplied text or imported corpus document. Rejections, flagged approvals, incomplete evidence, malformed responses and changed authority are withheld. YouTube always requires a human School/Admin viewing and transcript-completeness check because the model receives supplied text/metadata, not video pixels or audio. Changing the policy, model connection or class suitability context invalidates existing decisions.

## Teacher workflow

Submit either a YouTube HTTPS link or a supplied text copy with its attribution URL. YouTube requires a transcript, original teaching notes, confirmation of permission to use the material and, optionally, a start/end segment in seconds. Enter segments in the form; timestamp/playlist URLs are rejected. The server accepts a single canonical video identity, retrieves bounded public oEmbed title/author metadata and discards embedded HTML and thumbnails. It never follows an arbitrary source URL or accepts supplied iframe markup. Staff must provide a transcript they are entitled to use; arbitrary third-party captions are not scraped.

Run **Review** explicitly. The assigned model receives only the source snapshot, class title/curriculum and school policy notes, with a fixed rubric for embedded instructions, completed student answers, age suitability, harmful content, personal information, factual uncertainty, curriculum fit, rights, incomplete evidence and advertising/links. Student drafts, photographs, learning sessions and integration keys are excluded. The model returns enumerated findings and coverage only. It cannot write new lesson prose or follow tools/links.

When human approval is required, a School/Admin reviews the exact version, source hash and agent decision. A clean decision is required; a human cannot override a rejected or uncertain agent result through the approval endpoint. For YouTube, the human also confirms they watched the entire approved video or segment and verified the supplied transcript's completeness and match. Correct the material/policy and run a new review to resolve a finding. Editing, revoking or allowing a review to expire removes student access.

## Existing course materials and lesson assembly

Before an audit agent is assigned, existing shipped reviewed source packs and human-authored local materials retain the preceding human-corpus approval workflow. This change does not claim those historical sources have already received an agent review. New external submissions always require the registry workflow.

On first assignment, the school enters mandatory review. Use **Import current course corpus** to queue each public teaching passage, including bundled public-source summaries and local class resources. Teacher-only materials are excluded. Import is idempotent for an unchanged source; edits produce a new review candidate. Student access to school-wide text without a class is blocked in this mode: attach it to a class and review its exact content. Existing standard-alignment records remain planning metadata, not an automatically approved teaching passage.

Approved external notes/copies become public course-corpus sources. Imported corpus documents are associated with their originals and do not create duplicate passages. Refresh and approve the changed course corpus, then approve its teacher profile again before automatic Q&A or private lesson assembly. The selector may select the approved video's teaching notes and attach a controlled player reference to a private lesson. It cannot invent a video ID or embed URL.

Current source approvals are checked during retrieval, before a model send, before release, and when students reopen lesson history or request playback. Revoked or stale student content is withheld without rewriting the original session evidence. Authorized reviewers retain the historical source, decision and released lesson record. An already displayed browser page or already loaded third-party player cannot be recalled remotely; reopening/loading checks the current decision.

## Player and coverage boundary

Student pages contain a local placeholder, with no third-party thumbnail, iframe, prefetch or video request before an explicit acknowledgement and **Load reviewed video** action. That action obtains current server authorization and rechecks public metadata. A metadata outage withholds that playback attempt; an unchanged source can be loaded after recovery. Changed metadata durably blocks playback and source use until staff update and review a new snapshot. Staff can explicitly preview a pending video for review; it remains unavailable to students.

The server generates a privacy-enhanced `youtube-nocookie.com` embed with no autoplay and no student, class or session identifiers. The required referrer reveals the application origin only. A saved lesson stores a resource reference, never an enduring playable URL. Reviewer session replay stays inert. The player is YouTube's service: advertisements, related content, off-site navigation and changed video bytes are outside this text review. Metadata equality does not prove the underlying video is unchanged. Short expiry and human viewing reduce that gap without eliminating it.

YouTube documents [privacy-enhanced embedding and child-directed site designation](https://support.google.com/youtube/answer/171780?hl=en). Privacy-enhanced mode does not eliminate all third-party processing or advertising. Operators must complete the applicable YouTube site designation before student production use. The [player parameter reference](https://developers.google.com/youtube/player_parameters) explains that `rel=0` limits related-video selection but does not remove recommendations, and start/end controls are playback preferences rather than access controls. [Required player identity](https://developers.google.com/youtube/terms/required-minimum-functionality) explains the HTTP referrer requirement. [Caption download](https://developers.google.com/youtube/data/reference/rest/v3/captions/download) requires appropriate authorization; the application does not assume arbitrary transcript access.

## Evidence, migration and packaging

Immutable records retain every resource snapshot, policy revision, valid review result and publication decision. Review jobs allow pending admission/send markers and become immutable at completion/withholding. A school-wide reservation prevents parallel/ambiguous retries; terminal idempotent replay never resends. The audit chain records source hashes, policy/model context, fixed findings, usage, uncertainty, publication, revocation and playback admission. It does not record hidden reasoning, arbitrary invalid provider prose, video bytes or third-party viewing telemetry. External retained audit checkpoints remain a production requirement.

Run the explicit owner migration to **schema 4** before admitting the rebuilt API. It adds the external-review marker and expands ORM/SQLite/PostgreSQL immutability protections, preserving schema-3 markers, existing identities and prior audit bytes. The runtime role retains no migration, trigger, audit-rewrite or credential-minting rights. No new Core grant, AWS service, OAuth video token, bucket or model protocol is required.

The API and frontend must be rebuilt together, validated and released with a fresh immutable private-ECR image pin. The current source package is staged locally; production has not been changed by this feature. Review tests use synthetic records and mocked model/metadata transports; they do not establish live video availability, actual model quality or production acceptance.
