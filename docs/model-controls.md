# Model interfaces and instructional controls

## Model interface

Homework Help now has an explicit **generative exception**, approved separately by a human School/Admin. Three pinned model selections perform triage/direct help, optional AI-teacher responses and independent output review. Students need no course enrollment. A single triage operation identifies the topic and drafts its own response; when no admitted AI teacher matches, that draft goes directly to safety review without a separate tutor request. An explicitly approved public school AI persona can join even outside its classes, using no protected class materials. Human-taught subjects and base AI profiles remain supported. It generates plain-text explanations, analogous examples and questions, with server-owned citations; it may not write student submissions or complete assessed work. Strict parsing, deterministic checks, current authority/snapshot validation and a separate safety verdict precede release. Models receive no tools or publication authority. These controls cannot guarantee factual correctness or catch every work-completion attempt. Assignments, Lesson Q&A, private curated media and shared publication keep the narrower selection controls below. See [the complete Homework Help contract](homework-help.md).

Version-2 human approval pins the configuration, public school persona option and exact connection snapshots for all three phases; any material change requires fresh approval. Older approvals are not widened, and stable configuration/session IDs and immutable historical evidence are preserved. Pictures require explicit student consent and approved image capability for triage, tutoring and review. Each phase persists a send marker before I/O. Uncertain inference is never automatically retried. Exact visible phase evidence and generated replies remain private and auditable, without collecting hidden model reasoning. Metadata-only Core delivery retries use a separate outbox and never invoke these models.

The initial runtime uses an administrator-defined OpenAI-compatible Chat Completions selection interface with manual model allowlists. This is a protocol contract, not a promise that every provider/model implements it. Save/edit does not contact a provider. Connections keep credentials encrypted server-side and return configured status only. Empty replacement preserves the key; explicit clear removes it. Endpoint changes require fresh review and must not forward credentials to untrusted destinations.

The selector is stateless and bounded. Assignment tutoring receives an assignment/policy snapshot, the student's attempt/question and approved choice IDs, then returns one choice ID. Course Lesson Q&A receives exact admitted public teaching passages and returns one document ID. Server-side retrieval supplies those passages; the model has no retrieval tool, browser, uploads, code execution or document authoring. The application validates the exact schema locally; schema prompting or provider structured-output support alone grants no trust. No raw provider-generated prose is displayed to students. Released assistance is approved instructor text or an exact approved public-source excerpt with fixed style prompts and citations.

Where supported, request `store: false` explicitly. This setting is not a zero-retention guarantee: provider abuse monitoring, account terms and processing controls still require review. The provider request/usage schema follows the [official Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create); review [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data) when using that provider. No provider credentials or live calls were used in package tests.

## Fine-grained policy

Bind assistance to an assignment and a versioned approved hint bank. Controls include disabled/curated/Socratic modes, required student attempt, maximum session turns, input/output token bounds, approved connection/model, and bounded selection choices. Disabled means no inference. Curated mode uses stored teacher-authored text without model traffic. Socratic mode permits the model only to select an approved question. Curated mode can use both approved hints and questions. Reject unknown fields/IDs, oversized/free-text responses and invalid/missing usage. A failed selection supplies no unreviewed fallback answer.

Hard turn limits and conservative prompt-byte/output-token reservations bound resource exposure. The reservation ceiling is not a provider tokenizer guarantee. Actual reported usage is recorded separately. They do not establish a currency budget unless connection prices and reservation/accounting are separately implemented. Do not describe token caps as dollar ceilings. No automatic retries or fallback inference are permitted after uncertain billing. A pending operation blocks further calls. A completed withheld operation retains its reservation; a new explicit request with a new idempotency key may be admitted within the remaining limits. Administrators can disable live traffic globally and connections individually.

## Instructional assurance

The assignment/Q&A selector architecture below prevents a model from introducing newly generated answer prose into those outputs. The separately approved Homework Help exception above generates reviewed explanations and therefore has a different, risk-based refusal boundary. It does not validate the pedagogy of teacher-authored content or stop students using outside tools. Review hints before publication, test adversarial requests and configure assistance off for independent assessments. Model selection accuracy affects which approved help is chosen, but cannot bypass the approved-content boundary.

The approved interactive policy permits automatic tutoring inside a human-approved behavior profile and course corpus. The initial course implementation explains through exact source excerpts, with tone/detail/reflection chosen from fixed templates. School/Admin approves the profile, current public corpus and explicit model policy. Daily UTC requests and conservative token reservations are shared across all profiles for each student/course; pending sends block even after the daily reset. Teacher-only sources never enter the student Lesson Q&A prompt or excerpt candidates. Assignment-specific attempt and output rules remain unchanged.

An additional approved opt-in permits private student lesson curation from task descriptions and, with separate reviewed image capability and explicit student confirmation, bounded assignment photos. One text/image selector call returns only admitted document, associated visual and fixed reflection IDs. The server assembles exact public-source passages and trusted versioned interactive diagrams; optional browser read-aloud uses that same text. The image bytes contribute to conservative reservations, are encrypted when admitted and never embedded in audit output. Q&A/curation share quotas and uncertain-send barriers. No generated transcription, image markup, essay or new model prose is released. See [private curated lessons](student-curated-lessons.md).

An app-managed AI persona has no upstream principal or Teacher API rights. Core-bound profiles require fresh independent authorization of the selected binding before send and release as well as local actual class authority and the agent gate; revoked bindings never revert to managed personas. All profiles still require the global live-model gate. See [teachers and standards](teachers-and-standards.md) for the exact model-policy fields and source/currentness controls.

Freeform Homework Help explanations and analogous practice now use the separately approved capability described above. Essay rewriting, exact assessed-task completion and automated grading remain outside that capability. They must not be enabled by simply changing a prompt. Assignments, lesson materials and feedback retain human publication approval. The initial package gives instructors an inspectable tutoring surface while preserving their ability to use different administrator-approved model endpoints.

## School audit-agent policy

A separately assigned school model reviews supplied public teaching text/metadata with a fixed risk-code schema; no generated prose or tool calls are accepted. Admin policy may permit clean text/corpus automatic approval, while YouTube requires human viewing and transcript attestation. Source, class context, policy, connection/credential revision, review age and revocation are checked before use. School-wide UTC reservations and pending-job blocks apply independently of student lesson quotas. Saving the assignment grants no API authority and makes no model call. Review prompts exclude student sessions, drafts, photos and secrets. See [external media review](external-media-review.md).
