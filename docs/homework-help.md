# Homework Help

## School AI assistant

Homework Help is a private, model-provider-neutral chat workspace for an authenticated student in a school. Course enrollment is not required. Conversations appear on the left and the selected conversation and composer on the right; students can start a conversation, reopen history, ask a written question or attach permitted homework photos. Routing is automatic. The screen stays in this chat workspace when the school assistant is unavailable and explains that school setup is required. It does not silently substitute the enrollment-dependent legacy flow. Earlier guided-lesson conversations retain their separate historical contract below.

In School setup or Administration, open **Homework Help AI**. Select existing school connections and exact allowed models for triage/direct help, AI teacher responses and independent output review. Configure the assistant's name, biography, bounded behavior profile, daily turn/token limits and input/output bounds. Save a draft, then explicitly approve that exact revision as a human School/Admin. Approval binds the connection snapshots as well as the settings. Editing a connection, credential, model or configuration invalidates admission until reviewed again. The deployment-wide live-model switch remains a separate default-off control. This configuration does not enable live traffic by itself.

The triage assistant receives server-admitted enrolled-course descriptors, bounded conversation context and, when explicitly enabled by the school's approved configuration, approved public school AI-teacher metadata. It identifies the topic and can bring in a matching AI teacher. When no suitable teacher exists, school AI teachers are disabled, or the match is uncertain, that same triage operation supplies the explanation or a natural follow-up question. The separate tutor model is not called on this fallback path. Every generated reply still receives independent safety review. Students need not choose a course or teacher before asking. The assistant cannot grant enrollment, impersonate a human teacher, browse arbitrary websites or call tools. It can generate explanations, analogous examples and guided practice. It must not write a submission, complete an assessed worksheet or produce an essay for the student. Deterministic checks and a separate safety-model verdict gate each reply; failed, malformed or uncertain operations release no generated answer. These checks reduce risk but cannot guarantee correctness or catch every completion attempt. This exception does not widen assignment tutoring, Lesson Q&A, curated lessons or shared lesson publication.

A school may allow approved AI teachers to join even when the student is not enrolled in one of their classes. This uses the public approved teaching identity, expertise and behavior, with current profile/teaching-authority checks. It does not enroll the student or expose the teacher's class materials. Non-enrolled handoffs keep the conversation's course scope empty: no class assignments, protected passages, private class context or class-teacher review access is added. School/Admin retains full authorized review. Human teachers are not impersonated; a human-taught subject can still receive direct triage assistance.

The server optionally supplies current, approved **public teaching passages**, never teacher-only documents or standards-summary placeholders. Exact grounding snapshots and admitted source references are retained. Course and assignment links come from server-owned records; the model may select only offered reference IDs. Displayed text is bounded plain text, without generated HTML or arbitrary URLs. Follow-up context includes only bounded currently admitted messages from the relevant course/general/persona context. Enrollment is checked whenever protected course context is used; school membership, approvals, connections, preferences and source admission are checked around sends, release and replay. Revocation withholds previously displayed assistance without rewriting its historical evidence.

The generation approval boundary advances to version 2 because the triage model now generates direct help and can admit school AI personas. Existing configuration/session record IDs and immutable history remain stable. A human School/Admin must review and approve the new behavior; old approvals are not silently widened. The saved configuration exposes the school-AI-teacher choice in its review. This change needs no new database schema or Core permission.

Students complete the existing nine-question intake. Their bounded learning weights guide this assistant through a stable school-specific preference scope; they cannot override its system rules. Released AI messages accept the existing structured style/helpfulness/accuracy feedback. Style adjustments remain personal and bounded. An accuracy rating flags a concern; it does not certify an answer or silently rewrite shared teaching material.

### Photographs and durable evidence

Up to two normalized assignment pictures may accompany a question, within the existing 400,000-byte HTTP bound. Image use requires an approved image policy, explicit capability attestations for **all three models**, and student confirmation naming their destinations. Triage, tutoring and output review receive the actual normalized pictures when admitted; the reviewer can therefore compare proposed assistance with the photographed task. Photos remain encrypted in the private message. Replay/export JSON contains descriptors and hashes; separately authorized, audited image reads return private no-store JPEGs. No photo is sent without consent.

Schema 11 protects immutable assistant revisions, approvals, sessions and phase-send records, and seals terminal AI messages. The independent PII key encrypts local-family messages, photos, prompt/result evidence and related audit payloads before audit hashing. Evidence records the student's question, exact bounded phase prompts, model/policy/configuration/grounding snapshots, visible validated provider results, usage, routing, refusals, withheld results and exact released response. It excludes hidden model reasoning. Persisted send markers precede every external phase; final evidence commits before a reply reaches the student.

An idempotent retry reads the same durable operation. Changed input under its key is rejected. A process interruption or uncertain model response is observed through history and is **never automatically resent**. A human School/Admin can review the pending operation and explicitly close it as uncertain using its exact reviewed snapshot hash and a required reason. Closure seals a withheld result, preserves every send/result event and releases the student's pending barrier without another inference; concurrent changes require a fresh review. A late active phase cannot overwrite that terminal decision. The UI explains pending/withheld states rather than silently sending again. AI session creation is limited to 100 per student per UTC day and 100 messages per session. New sessions do not reset the approved daily message/token allowances; clarification, blocked admissions and stored pictures also have independent bounded storage allowances. These limits reserve conservatively and record provider usage separately; token limits are not currency limits.

Human School/Admin reviewers can discover and read complete authorized school conversations, including pre-triage questions. A currently assigned Teacher, including an authorized Core teaching agent with the audit capability, receives only that class's interactions through the class review routes. Other courses, general questions and full provider prompt evidence are excluded from that class projection. All reviews and image reads are audited. Full tenant evidence remains available only under the existing Admin export boundary.

### AI API

All routes retain existing authentication, tenant/current membership checks and browser mutation CSRF controls. Request objects reject unknown fields. Configuration is restricted to human School/Admin; asking requires a current human Student school membership and completed intake, with no course-enrollment requirement.

| Operation | Route |
| --- | --- |
| Read/save school configuration | `GET/PUT /api/homework-help/configuration?school_id=<id>` |
| Approve exact saved revision | `POST /api/homework-help/configuration/approve?school_id=<id>` with `{revision_id}` |
| Available assistant, optional enrolled-course context, own paginated conversations | `GET /api/homework-help/ai?school_id=<id>&cursor=…` |
| Start/reconcile own session | `POST /api/homework-help/ai/sessions` with `{school_id?, idempotency_key}` |
| Read own session | `GET /api/homework-help/ai/sessions/{id}` |
| Ask with automatic routing | `POST /api/homework-help/ai/sessions/{id}/messages` with bounded question, optional pictures/consent/course, `routing_mode: auto|general` and idempotency key |
| Read an authorized normalized photo | `GET /api/homework-help/ai/sessions/{id}/messages/{message}/images/{image}` |
| Paginated school review catalog | `GET /api/homework-help/ai/review-sessions?school_id=<id>&cursor=…` |
| Complete school review | `GET /api/homework-help/ai/sessions/{id}/review` |
| Class-only review catalog/session | `GET /api/courses/{course}/homework-help/review-sessions`, `/api/courses/{course}/homework-help/sessions/{session}/review` |
| Close an uncertain pending operation without resend | `POST /api/homework-help/ai/sessions/{id}/messages/{message}/close-uncertain` with `{expected_sha256, reason}`; human School/Admin only |
| Personal released-message feedback | Existing `/api/me/feedback`, with the AI message ID as `turn_id` |
| Authorized school/tenant metadata delivery health | `GET /api/homework-help/audit-delivery?school_id=<id>` |

The AI index and school catalog return `next_cursor`; use that opaque cursor to continue rather than constructing offsets. Exact typed schemas are in the generated [OpenAPI reference](reference/openapi.json). AI sessions use separate record kinds and endpoints so legacy conversation evidence and release rules retain their meaning. Voice integration for these generated replies remains deferred; existing voice playback is limited to the legacy released teaching flow.

### Core pipeline and independent archive

Each local audit append atomically queues an allowlisted metadata event. A separate restricted worker delivers it to the existing Core pipeline with stable event IDs and safe duplicate reconciliation. Core receives hashes, pseudonymous references, status/usage and phase metadata; **no questions, replies, photos, names, credentials or PII key**. The API never waits for Core delivery or retries model inference as queue work. A separately scheduled archive retains original encrypted audit evidence. Delivery health and archive freshness are independent signals. See [audit delivery and activation](audit-delivery.md), [encryption testing](family-accounts.md) and [archive recovery](session-archive.md). Source packaging does not activate either worker in production.

## Legacy approved-excerpt mode

Homework Help is a private conversational workspace for an enrolled student. It identifies a course, brings in that course's approved AI teacher and keeps the question, routing decision, attachments, teacher selection and released teaching evidence in the student's learning record. Students may correct the course or choose another admitted teacher on a subsequent message.

The triage component is deliberately narrow: it ranks the names, descriptions and subject labels of currently enrolled courses that have an enabled, human-approved private lesson teacher. A distinctive course match can be selected automatically. A follow-up can continue the current course and stable teacher. Ambiguous matches ask the student; a photograph without written context always asks for an explicit course before any model send. Triage makes no external model call, reads no image content and cannot grant access to a different course or teacher.

## Conversation and teaching boundary

After handoff, the service invokes the existing private curated-lesson operation. It uses the current approved behavior, public teaching corpus, external-media decisions, model connection and image capability. The model chooses existing source, visual and reflection IDs. The server assembles exact approved passages and fixed prompts. It cannot display provider-generated assignment answers, solve an uploaded worksheet, write an essay or edit student work.

A follow-up includes the latest question plus at most three earlier student questions, each truncated to 1,000 characters. Earlier questions must belong to this conversation, course and teacher, and their associated teaching turns must still be released and currently admitted. They are included only when the complete input fits the teacher's approved input limit. No other course's conversation, teacher-only materials, photos or model-generated text enters that context. The immutable context snapshot records the exact included message IDs and text.

Course links are created by the server. Relevant assignment links are selected from the currently enrolled course using assignment titles/module labels, with a maximum of three. They point to the application's course and assignment views, using `/#course=<id>&assignment=<id>`. Approved source citations remain attached to each teaching passage. The student cannot supply a destination URL or another student's submission as a reference.

Homework Help shares all private-lesson course quotas with Lesson Q&A and curated lessons. Opening a new conversation, changing teacher or using a different activity does not reset the student's UTC course budget. The same intake and bounded personal learning weights apply. A released underlying lesson turn can receive the existing structured accuracy, helpfulness and presentation feedback.

## Pictures and privacy

A question can include up to two assignment images through the same bounded image input and normalization utilities as private curated lessons. The service keeps normalized JPEG images encrypted in the student-owned message; audit events contain names, dimensions and content hashes rather than image bytes or ciphertext. The student's scoped image endpoint requires current student school membership. The model receives a photograph only after explicit student confirmation and an approved image-capable teacher policy. A clarification response has not sent the image to a model.

The browser retains the proposed question and photographs while asking for a course/teacher choice. Confirming the destination creates a new immutable message with its own idempotency key. Current teacher approval and image/model policies are checked again by the existing lesson lifecycle immediately before send and release.

## Durable records, retries and review

Conversations are immutable `homework_session` records pinned to one school and student. Each incoming question is an immutable `homework_message`, including the routing decision, attachment metadata, encrypted attachment storage, original question and exact bounded conversation context. Its private lesson key links to an existing sealed `lesson_turn`; an immutable `homework_outcome` stores the exact validated turn pointer after admission. Normal history reads load that one turn rather than transferring every course conversation and encrypted photograph. Interrupted receipt recovery uses one database-filtered exact-key lookup, rejects ambiguous matches, and an explicit POST reconciliation seals the recovered pointer. Provider transport and terminal release evidence remain in the established course lesson session.

The service commits the incoming message and handoff evidence before invoking the lesson operation. A normal admission refusal before a lesson turn exists produces an immutable `homework_outcome` with a final blocked status and an explicit no-send audit event. A process interruption after saving the question but before lesson admission is shown as not started and can be resumed only through an explicit student action, using the original stored payload and lesson key. That operation commits its send marker before external I/O and its terminal audit before release. Exact duplicate message requests reuse the same lesson key. Changed input under the same key returns 409. An uncertain provider result is never automatically retried. A missing homework receipt after a durable lesson result can be reconciled without a second provider call.

Student history rechecks current course, approved teacher, actual bound-agent authority and current source reviews before showing released teaching content. Revoked content is projected as withheld; historical records remain intact. The student can still review their own original question and school-scoped private upload.

School/Admin humans can discover the school's conversations through the audited review catalog and read an entire conversation through the separately audited review endpoint. Their protected image reads also cover private photographs retained before course clarification. Teachers receive only the existing course-specific lesson session and its handoff event, avoiding access to unrelated pre-triage or other-course questions. Full tenant audit exports and the separate retained archive contain the Homework Help events. The per-conversation review projection is a partial chain and does not replace an independently retained complete tenant chain.

## API

All routes require normal authenticated application access and mutation CSRF protection. Inputs forbid additional keys. The optional index school filter is checked against current human Student school membership.

| Operation | Route | Input/result |
| --- | --- | --- |
| Current routing catalog and conversations | `GET /api/homework-help?school_id=<id>` | Enrolled courses, currently admitted teachers, and up to 100 own conversation descriptors |
| Start/reconcile conversation | `POST /api/homework-help/sessions` | `{school_id?, idempotency_key}`; school may be inferred only when unambiguous |
| Explicitly resume a saved, unsent question | `POST /api/homework-help/sessions/{session_id}/messages/{message_id}/resume` | `{}`; original stored payload/key, no action for an existing pending/terminal lesson |
| Own conversation | `GET /api/homework-help/sessions/{session_id}` | Descriptor and immutable message projections |
| Ask/clarify/correct course | `POST /api/homework-help/sessions/{session_id}/messages` | `{message, images?, image_use_confirmed?, course_id?, teacher_profile_id?, idempotency_key}` |
| Own normalized picture | `GET /api/homework-help/sessions/{session_id}/messages/{message_id}/images/{image_id}` | Private, no-store JPEG; audited access |
| Human school administrator review catalog | `GET /api/homework-help/review-sessions?school_id=<id>` | Up to 100 currently authorized school conversation descriptors, including pre-triage sessions |
| Human school administrator review | `GET /api/homework-help/sessions/{session_id}/review` | Safe immutable message/lesson evidence and partial session events; audited access |

Session descriptors expose their original idempotency key. Message projections expose their original key, `status`, `error`, `resume_available`, `triage`, existing curated `turn`, attachment descriptors and server references, allowing the browser to reconcile an uncertain response through a GET. Message text is bounded to 10,000 characters; the approved teacher limit can be lower. The image-aware request route is bounded to 400,000 actual HTTP bytes. Conversation creation is limited to 30 per student per UTC day, with at most 100 messages per conversation. An independent allowance caps new Homework Help questions at 100 and normalized photographs at 10 MiB per student per UTC day across all schools and conversations. Clarifications and blocked questions count toward storage admission; exact idempotent retries do not. The allowance uses recorded scalar byte metadata and never decrypts historical pictures to calculate usage.

`status` is `clarify` before an unambiguous course/teacher selection or follows the underlying lesson's `pending`, `blocked`, `withheld` or `released` state. A stored question with no lesson turn and no terminal outcome is `pending` with `resume_available: true`; the browser explains that it has not started and requires an explicit Resume question action. A linked pending/uncertain lesson and a terminal blocked outcome never permit a new send. `turn.id` is the existing learning-feedback target. A rejected ownership lookup returns 404; missing current class/teacher permissions return 403; stale idempotency use returns 409; malformed or oversized typed context returns 422/413.

Voice integration uses the same currently admitted, released teaching text. See the voice integration documentation for the explicit approved synthetic voice catalog, provider consent, bounded text/audio and transport controls. Homework Help does not create a separate realtime model channel or bypass the lesson release decision.
