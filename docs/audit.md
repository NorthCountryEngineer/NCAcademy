# Session evidence and audit controls

## What instructors can establish

Replay preserves the student's submitted attempt and questions, the assistance actually displayed, assignment/policy/model snapshots, denials, provider errors and usage. Instructors can inspect progress over time and compare the student's final submission with the assistance supplied. It records service-visible evidence; it cannot prove independent authorship, record work done elsewhere, or expose hidden model reasoning.

Course Lesson Q&A has a separate stable student/course session and no student-draft payload. Its replay includes exact teacher-profile revision/mode, approved corpus, admitted public passages and hashes, actual question, prompt, visible provider document selection, normalized usage, UTC budget day/reservation and before-send/release authorization decisions. The student sees only their own question/outcome/excerpt/citations. School and session exports include lesson evidence under the same current reviewer permissions and access logging. Quota resets and teacher changes preserve the full historical course session.

Private curated lessons share that course session. Audit includes the task description, normalized photo hashes/dimensions, preferences, exact source/media candidates and released bundle, wire-request SHA256, validated plan/usage and learning actions/reflections. Admitted photo binaries are encrypted in the immutable turn and excluded from all JSON replay/exports; current scoped image reads decrypt/hash-check and log access. Pre-send blocked requests retain only image metadata. Invalid provider prose is hash-only to avoid echoed photo/key data entering evidence; valid selection IDs remain readable. Read-aloud/section actions record intent rather than proving comprehension. Independent retained export hashes plus controlled binary retrieval/backup are required to reconstruct and protect complete photo evidence. See [the photo lifecycle](student-curated-lessons.md).

## Event obligations

Google Classroom integration evidence records local operation/course/school IDs, phase markers, counts and sanitized outcomes. Imported Google assignment text, account/remote course IDs, URLs and credentials are excluded from permanent generic audit/session/archive data. Mutable private account/link envelopes are encrypted and cleared on disconnect; idempotency retains a keyed irreversible fingerprint. The student's independently authored Homework question and released guidance retain the existing tutoring evidence. An assignment read receipt establishes access at that moment, not the complete contents of the external assignment or proof of work done in Google. See [Google Classroom](google-classroom.md).

Core-backed group chat retains exact admitted text, authenticated author, school/class scope, stable request identity, send attempts and verified Core delivery evidence. Every membership transition has an immutable event; AI posts require a human School/Admin publication decision and fresh original-agent authority. Reads record counts of admitted and withheld upstream messages. Core's application/AI actor is distinct from the actual local author; unknown upstream content has no local authorship proof and is withheld. Schema 8 protects immutable chat kinds and terminal attempts. Full tenant audit export includes command/outcome text for Admin review; current group ACLs gate ordinary history and receipts. Core retention and independent application evidence retention must both be verified. See [group chat](group-chat.md).

Student preference changes append immutable revisions. Each tutoring request pins its exact revision, algorithm and effective presentation weights. Student feedback pins the released interaction, current student/course/teacher scope, accuracy/helpfulness ratings, explicit style targets and resulting weights. Feedback cannot edit the original turn or another student's configuration. Accuracy concerns are review flags, not model instructions or automatic source corrections. Personal settings reset future adaptation without erasing historical evidence. See [learning preferences](student-learning-preferences.md).

Record UTC timestamps and strictly ordered events, tenant/school/course/student/session and operation IDs, actor, event kind and canonical payload. New agent actions attribute principal kind, Core account/binding/consumer, environment/task, local placement and the actual operation; a teacher agent never borrows a human actor ID. Human publication decisions identify the proposing agent and reviewing human. Include immutable assignment/policy/hint-bank and model connection versions. Each record incorporates its predecessor hash. Log tutor-off decisions, missing-attempt blocks, exhausted limits, malformed/withheld output, uncertain sends, failed providers, successful release, replay reads and exports. No API permits audit edit/delete. Never place credentials or authentication tokens in events.

Write request/send evidence before network I/O and completion/usage/output evidence before returning content. An audit failure prevents assistance. A process exit after send can leave an uncertain request; its idempotency key must never trigger an automatic replay. Administrators investigate unresolved pending operations instead of resetting them for replay. A completed withheld outcome keeps its reservation; the same idempotency key never sends again. A new explicit user request may use remaining allowance. Do not run background retry loops for provider traffic.

Schema 3 protects immutable teacher revisions, corpus snapshots and corpus approvals in both the ORM and SQLite/PostgreSQL. Pending assignment/lesson turns may record a send marker and terminal outcome; terminal turns cannot be rewritten, disguised as another record kind or deleted. These triggers preserve evidence against the runtime login, not a privileged database administrator. Migration appends a version receipt without rewriting historical records or audit bytes.

## Tamper evidence and production retention

Application append-only writes and a hash chain provide evidence of modification relative to a trusted head. A hash chain stored beside the data does not resist a privileged database rewrite, deletion of a chain tail, or replacement of the database. The production API role does not own the schema and receives only SELECT/INSERT on audit events; UPDATE/DELETE/TRUNCATE and schema DDL are denied. The mutable audit head permits SELECT/INSERT/UPDATE to advance the chain. A separate owner-only migration identity creates schema, triggers and runtime grants. SQLite and local Compose owner credentials are not a production audit boundary.

The original production retention path uses an independently controlled encrypted S3 bucket with Object Lock retention and operator-run KMS-signed checkpoints. Capture the tenant ID, sequence/count, last event hash, timestamp and exact export SHA256 in signed checkpoint material. Retain the export, checkpoint material, signature, key/algorithm metadata and object-version identifiers together outside the database trust boundary. Verify the KMS signature and export checksum before trusting the head.

The application has no AWS task role, archive-write permission or KMS signing permission. This revision also packages a separate read-only database archive worker and private S3-compatible Kubernetes storage option; see [session archiving](session-archive.md) for exact encryption, signature, cursor, monitoring and recovery contracts. Worker/archive keys remain outside the student-facing API. An initial migration checkpoint alone does not retain later student activity. Before admitting real students, verify the running archive's retention configuration, key/archive authority separation, checkpoint cadence, monitoring and restore path. Do not label an unanchored database WORM/immutable or treat a signed but unretained checkpoint as a complete retention control. Cluster/storage administrators remain privileged; retain backups and trusted heads outside their ordinary control.

Choose checkpoint cadence and retention based on accepted loss/exposure windows; assign an operator until an independently reviewed automation exists. Monitor missing checkpoints and unresolved send markers. Exercise verification against both altered content and deleted tails, then restore a synthetic export and verify its trusted head before production acceptance. Keep signer/deletion authority separate from application/database credentials. Record reviewer access to external archives in the archive access log as well as the application log.

## Access, privacy and lifecycle

Full student replay belongs to Admin across the tenant, human School administrators within their assigned schools, and human or agent Teachers within assigned classes with current `academy-audit`. Students see their own permitted conversation. Agent teachers may review observable assistance, immutable submissions and saved-draft versions captured by the session audit. Direct student-draft endpoints remain student-owned. They cannot read the tenant audit. Scope every search/export by tenant, school and course. Revoke reviewer access through Core and local school/course membership. Exports contain student records: store them in restricted operator storage, never Git, public docs or build artifacts.

School and session exports are explicitly partial evidence. Omitting other schools' events leaves gaps in the original tenant chain; do not renumber/re-hash selected events or label that view a verified complete chain. Full tenant export and verification remain Admin-only and use the unchanged tenant head. The additive school migration preserves original event bytes/hashes and identity actor IDs; it does not rewrite historical payloads to add school fields. Scope legacy evidence through its preserved resource/class mapping, and fail closed when the mapping cannot establish access.

There is no automatic audit purge in the initial package. Define record retention, legal holds, backup expiration and an approved deletion process before using real records. Expiring a local session must not silently delete its evidence. The production runbook must include breach/access response, authorized record export and recovery ownership.

## External source decisions

External submissions retain immutable snapshots and content hashes. Agent assignment creates an immutable policy revision. School-scoped jobs reserve before send, persist a durable marker, validate exact enum findings/usage and seal terminal outcomes; uncertainty prevents automatic retries. Review/publication records pin source, class context, policy, model, coverage and expiry. The audit chain records assignment, queue/evidence access, submissions/imports/edits, review admission/send/result, human or policy publication, revocation, metadata changes and playback admission. No hidden reasoning, video bytes, private student records, secret keys or invalid provider prose is retained in review evidence. Playback admission is not evidence of actual viewing or understanding. Historical lesson evidence remains intact when revoked sources are withheld from student history. See [external media review](external-media-review.md).
